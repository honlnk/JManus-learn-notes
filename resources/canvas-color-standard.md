# Obsidian Canvas 颜色规范

## 📖 概述

本文档定义了 JManus 学习项目中 Obsidian Canvas 的颜色使用规范，确保所有图表在视觉上的一致性和可读性。

## 🎨 颜色映射 (ID 0-6)

Obsidian Canvas 只支持 7 种颜色，ID 范围为 0-6。超出范围的 ID 将显示为白色。

| ID | 颜色名称 | 视觉效果 | 使用场景 | 语义含义 |
|----|---------|---------|----------|----------|
| 0 | 灰色 | ⚪ | - | - (未使用) |
| 1 | 红色 | 🔴 | 标题、主入口 | **重要**、核心、入口点 |
| 2 | 绿色 | 🟢 | HTTP 入口、基础功能 | **开始**、输入、基础组件 |
| 3 | 橙色 | 🟠 | 执行协调、工具执行 | **执行**、处理、动态操作 |
| 4 | 黄色 | 🟡 | 执行上下文、异常处理、时间线 | **上下文**、状态、辅助信息 |
| 5 | 紫色 | 🟣 | Agent 相关功能 | **智能体**、AI 相关、决策 |
| 6 | 青色 | 🔵 | 工具回调、计划完成处理 | **工具**、输出、结果处理 |

## 📋 详细使用指南

- **适用场景**: 标题、主入口、核心概念

## ⚠️ 重要规则

### 1. ID 范围限制
- **有效范围**: 只能使用 ID 0-6
- **超出后果**: ID 7 及以上将显示为白色
- **验证方法**: 在 Canvas JSON 中检查所有 `"color"` 属性

### 2. 语义一致性
- 同类型的组件应该使用相同的颜色
- 相关功能的边应该与目标节点颜色一致
- 避免颜色滥用，保持视觉层次清晰

### 3. 边颜色规则
- 边的颜色应该与目标节点颜色一致
- 重要的连接可以使用实线，辅助连接使用虚线
- 避免使用超出范围的颜色 ID

## 🛠️ 实际应用示例

### 节点颜色示例
```json
{
  "id": "http-entry",
  "type": "text",
  "text": "HTTP 请求入口",
  "color": "2"  // 绿色 - 基础功能
}

{
  "id": "agent-execution",
  "type": "text",
  "text": "Agent 执行",
  "color": "5"  // 紫色 - 智能体相关
}
```

### 边颜色示例
```json
{
  "id": "http-to-coordinator",
  "fromNode": "http-entry",
  "toNode": "planning-coordinator",
  "color": "3"  // 与目标节点一致
}
```

## 🔍 颜色检查清单

创建新 Canvas 时，请检查：

- [ ] 所有节点颜色 ID 都在 0-6 范围内
- [ ] 同类型组件使用相同颜色
- [ ] 边颜色与目标节点颜色一致
- [ ] 语义符合颜色规范
- [ ] 没有使用超出范围的颜色 ID (7+)
